# 2026-10-14

## cbTemplatePalette（テンプレパレットくん）

- **共有カテゴリの保存先を Cloudflare R2 から Dropbox のフォルダに変えた**（[ADR-012](../docs/ai/decisions/ADR-012-template-palette-dropbox.md)。[ADR-011](../docs/ai/decisions/ADR-011-template-palette-shared-categories.md) の R2 の部分を置き換え）
  - `cbTemplatePalette/r2-worker/` と `src/r2Storage.ts` を削除した。サーバーは置かない。公開前だったので移行は無く、clientStorage に残った R2 の登録は読み飛ばすだけで消さない
  - 接続は OAuth 2.0 PKCE（App secret なし・`redirect_uri` なし）。「Dropbox に接続」でブラウザの許可画面を開き、表示されたコードを貼って接続する。verifier は UI のメモリだけ、SHA-256 は `src/pkce.ts` に自前で実装（RFC 7636 の例で確認）
  - refresh_token は clientStorage の `cbTemplatePalette.dropboxSession`、アクセストークンはメモリだけ。「接続を解除」で Dropbox 側のトークンを取り消してセッションを消す（共有カテゴリの登録とデータは残す）
  - アプリは Full Dropbox、スコープは `account_info.read`・`files.metadata.read`・`files.content.read`・`files.content.write` だけ
  - 「共有カテゴリを追加」ダイアログを「接続（コード貼り付け）・フォルダ選び（上へ・作成・このフォルダを選ぶ）・カテゴリ名」にした。共有フォルダの根は `ns:<namespaceId>` で指す
  - 読み書きは `src/dropboxStorage.ts`（download / upload / delete_v2）。`Dropbox-API-Arg` は ASCII にエスケープ、401 は 1 回取り直し、429 は `Retry-After` 待って 2 回まで。使う前にフォルダがあるか確かめ、消えたフォルダは作り直さない
  - カテゴリの印は「Dropbox」、読み込み中は「Dropbox から読み込んでいます…」、接続が切れたときは一覧の上に「Dropbox の接続を確認」ボタン
  - manifest の `networkAccess` は `https://api.dropboxapi.com` と `https://content.dropboxapi.com` だけにした
- typecheck・build・pack:share は通る。`DROPBOX_APP_KEY`（`src/dropboxAuth.ts`）は空のままで、入れるまで接続できない。Dropbox との読み書き（CORS を含む）は実機で未確認
- **共有カテゴリの保存先に Cloudflare D1（自分で立てる Worker 経由）を足し、Dropbox と選べるようにした**（[ADR-013](../docs/ai/decisions/ADR-013-template-palette-d1.md)）
  - 新規 `cbTemplatePalette/d1-worker/`。API は削除前の R2 Worker と同じ（`/v1/ping`、`/v1/spaces/<space>/objects/<path>`）。認証は Worker の secret `ACCESS_TOKEN`（Bearer、SHA-256 にして `timingSafeEqual`）
  - D1 の `objects (space, path, chunk, body, updated_at)` に、本文を UTF-8 で 1MB ごとに分けて入れる（1 行約 2MB の上限のため）。書き込みは削除と挿入を 1 回の `batch` にまとめる。1 件 25MB まで
  - プラグインは `src/d1Storage.ts`。`sources.ts` で保存先の種類ごとに振り分け、エラーの文言・読み込み中の文言・名前の初期値（スペース名）も種類で分ける。`STORAGE_ERROR` に `provider` を足し、「Dropbox の接続を確認」は Dropbox のときだけ出す
  - 「共有カテゴリを追加」ダイアログの上に「Dropbox」「Cloudflare D1」の切り替えを置き、D1 では URL・アクセストークン・スペース名を入れる。カテゴリの印は「D1」
  - manifest の `allowedDomains` に `https://*.workers.dev`、`devAllowedDomains` に `http://localhost:8787` を足した
- typecheck・build・pack:share、`d1-worker` の `npm run check` は通る。`wrangler dev --local` で、401・400・404・413、7.2MB の本文の分割と復元、上書き・削除、プラグインの `D1StorageAdapter` からの読み書きと接続テストを確かめた。Figma の実機（`*.workers.dev` の許可・CORS）は未確認
- **D1 の接続テストで、失敗の原因に近い案内を出し分けるようにした**
  - 報告: URL・トークン・スペース名を入れても「Cloudflare D1 に接続できませんでした」になる。ping の応答が `{"ok":true,"service":"figma-storage-api"}` で、`cbTemplatePalette/d1-worker` ではない別の Worker の URL だった（プラグインは `app: "cbTemplatePalette-d1"` を確かめている）
  - `d1Storage.ts` の接続テストが理由（届かない・別の Worker・R2 用 Worker・トークン違い・D1 の読み書きの失敗・スペース名）を返し、`sources.ts` の `testSource` が案内の文言にする。Worker の応答そのものは UI に出さない。一覧の操作中のエラーは今までどおり種類だけ
  - `d1-worker/README.md` に「接続テストが失敗するとき」（ping の `app` の確かめ方と対処の表）、spec に案内の一覧を足した
  - fetch を差し替えて 8 通り（別の Worker・R2 用・401・ping 404・届かない・PUT 500・PUT 400・成功）の案内を確かめた。typecheck・build・pack:share は通る
- **Dropbox の接続を削除して共有カテゴリを D1 だけにし、「⋯」→「設定…」に「共有カテゴリを使用する」（初期値オフ）を足した**（[ADR-014](../docs/ai/decisions/ADR-014-template-palette-shared-settings.md)。[ADR-012](../docs/ai/decisions/ADR-012-template-palette-dropbox.md) は廃止）
  - `src/dropboxAuth.ts`・`dropboxSession.ts`・`dropboxStorage.ts`・`pkce.ts`、Dropbox のメッセージと UI（保存先の切り替え・接続・フォルダ選び・「Dropbox の接続を確認」）を削除した。manifest の `allowedDomains` は `https://*.workers.dev` だけ
  - clientStorage に残った Dropbox の登録と `cbTemplatePalette.dropboxSession` は読まず・消さない。共有カテゴリの登録を保存し直すときも、読めない登録はそのまま残すようにした
  - 設定ダイアログ: チェックボックス「共有カテゴリを使用する」と「閉じる」。変えるとすぐ反映し、clientStorage の `cbTemplatePalette.useSharedCategories`（新規 `src/settings.ts`）に置く
  - オフのときは共有カテゴリをカテゴリメニュー・移動先に出さず、「共有カテゴリを追加…」も隠す。登録と D1 のデータは消さず、見ていた共有カテゴリからは「未設定」に戻す。隠れている共有カテゴリと同じ名前の通常カテゴリは作れない
  - すでに D1 の共有カテゴリを足していた人は、設定をオンにするまで見えない
  - typecheck・build・pack:share は通る。`src` と `manifest.json` に Dropbox は残っていない（コメントも含む）
