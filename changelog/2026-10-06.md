# 2026-10-06

## cbTemplatePalette（テンプレパレットくん）

- **画像を消さずに保存できるようにした**（[ADR-007](../docs/ai/decisions/ADR-007-template-palette-images.md)、仕様は [`docs/specs/cb-template-palette.md`](../docs/specs/cb-template-palette.md)）
  - 以前は画像のバイト列を保存せず、複製すると必ず単色（`#D9D9D9`）に置き換えていた。ファイルをまたいだ複製で「画像が消えた」ことになる
  - 保存のたびに、選択に画像があるときだけ「この選択には画像が N 個あります。画像を一緒に保存しますか？」を聞く。「画像を含める」「画像を含めない」「キャンセル」の 3 つのボタンで、Esc とカードの外を押すと保存自体をやめる
  - 同じ画像は 1 個として数える。塗った回数ではなく種類数
  - 「含める」を選ぶと `figma.getImageByHash().getBytesAsync()` でバイト列を取って保存する。復元時は `figma.createImage()` を作り、塗りのハッシュを貼り戻す
    - 4096px 超や PNG / JPEG / GIF 以外など、Figma が読み込めないものは保存できた範囲だけ貼り、残りは枠線にする
    - 初版（version 1）で保存して残っていた画像データも今回から復元に使う
  - 「含めない」を選ぶとバイト列は取らない。代わりに枠線のプレースホルダへ置き換える
    - 中身が無い図形は `frame("image")` を作り、中央に `text("image")`（`#D9D9D9`、サイズ 12）を置く
    - 中身があるノード（子を持つ、またはテキスト）は枠線の中に元のノードを置き、枠線だけ足す。型・子・テキスト・角丸・自動レイアウトはそのまま
    - 形の一部（線・ベクター領域・文字の途中）は消すと崩れるので、単色 `#D9D9D9` にする
  - コンポーネントは `meta.imageMode` にどちらを選んだか残す。同じファイルの元から複製するとき「含める」なら `clone()` したものをそのまま、「含めない」なら複製後に枠線へ置き換える
  - 保存形式を `StoredTemplateV3`（`data` + 任意の `images`）にした。version 2 のテンプレートはそのまま読める（画像は枠線に戻る）
  - ファイル書き出しは画像があるときだけ `version: 4` にして、`templates[].images` に `data:…;base64,…` を入れる。画像が無ければ version 3 のまま
  - `clientStorage` の上限は約 5MB のままなので、確認を出すときに容量も見て「含める」を無効にする。画像バイト列 + サムネイル余力（64KB）が残量を超えるとき
  - 読み込んだテンプレートは、ファイル内の `meta.imageMode` に従って複製時の挙動を戻す
- **サムネイルを画像込みで作るようにした**
  - 「含める」で保存したテンプレートのサムネイルは実際の画像になる。「含めない」なら枠線のまま
  - 画像を復元するとき、同じハッシュの `createImage` は使い回すので、サムネイルと実データの両方で作り直さない
- **グループの順番をドラッグで変えられるようにした**
  - グループの見出しは掴めて並べ替え処理も動いていたが、別のグループ見出しに載せるとヒントが出ず（`resolveDropHint` が `null` を返していた）、ルートに単独のテンプレートが 1 件も無い状態ではどこへも落とせなかった
  - いまはグループを見出しに載せると、上・下の半分で前後に並べ替えられる（グリッド表示は左右）。グループの中にいる行に載せても親グループの前後として受け付ける。グループは入れ込めない
  - ヒントの見た目は既存の `.template-group.is-drop-before / .is-drop-after` がそのまま効くので CSS は触っていない
  - 落とし先のスロット番号を DOM の並びではなく `tree` / `group.items` から引くようにした。絞り込み中は見えている並びと実際の並びが違うので、従来は 1 つ分ずれた位置へ落ちることがあった（グループだけでなく行の入れ替えでも同じ）
  - 半分で前後を決める判定は `halfBefore()` にまとめた。並べ替えの処理は `tree.ts` のままで、変わったのはヒント判定だけ
  - `resolveDropHint` の index と `moveNode` の組み合わせを 14 ケースで確認した。typecheck と build は通る。実機でのヒント表示は実機でのみ確認
- **名前をダブルクリックで変更できるようにした**
  - 一覧の行とグループ見出しの名前テキストをダブルクリックすると、「⋯」メニューの「名前を変更」と同じ入力欄が開く
  - 行をダブルクリックして複製する挙動は名前以外の部分（サムネイル・情報行・バッジ）のまま。名前テキストをダブルクリックすると複製ではなく名前変更になる
  - typecheck と build は通る。1 回目のクリックで `renderList()` して行を作り直すので、ダブルクリックが新しい行に届くかは実機で確認
- **カテゴリで一覧と保存先を切り替えられるようにした**（[ADR-008](../docs/ai/decisions/ADR-008-template-palette-categories.md)、仕様は [`docs/specs/cb-template-palette.md`](../docs/specs/cb-template-palette.md)）
  - カテゴリはテンプレートにつけるラベルで、グループ（入れ物と並び順）とは別物。入れ替えも並び替えもしない
  - ヘッダー右のボタンでカテゴリを選ぶと、**一覧がそのカテゴリの行だけに切り替わり、保存先も同時に変わる**。ツールチップに今選んでいる名前が出る（選んでいる間はボタンが青くなる）
    - ポップアップは「未設定」と登録済みの名前の並び。既定は「未設定」なので、最初はカテゴリの無い要素だけが見える
    - 名前の絞り込み（上の入力欄）とは AND で併用する
    - カテゴリで絞ったときのグループは名前の絞り込みと同じ扱い。中身が 1 件も合わないグループは隠し、一部だけ隠れるものはたたんでいても開いた状態で描く（折りたたみは保存されたまま）。中身が 0 件のグループ（作ったばかりのもの）は名前を絞っていない限り出したままにする
    - 選んだ値はその画面を開いている間だけで、次に開くと必ず「未設定」。画像の確認ダイアログを挟んでも同じカテゴリをもう一度送る
    - 「名前を変更」で登録名を書き換え（使っているテンプレートの `meta.category` もまとめて）。追加は見出しの「⋯」→「カテゴリを追加」で、名前は「カテゴリ N」で開くのでそのまま Enter でも打ってもよい。作った直後から保存先になり、一覧もそのカテゴリ（中身が無いので「該当なし」）に切り替わる
    - カテゴリの削除 UI は作っていない（追加と名前変更だけ）
  - 保存済みの 1 件は行の「⋯」→「カテゴリ」→ 名前で付け替え（現在のものは選べない）。一覧の行には表示しない
  - 保存データは `TemplateMeta.category` に名前を入れるだけ。`meta` は自由形なのでファイルの version は上げない
    - カテゴリの登録先は `cbTemplatePalette.categories`（まだ誰も使っていない名前も残る）
    - 読み込んだファイルが持つカテゴリは、こちらのレジストリに無くてもポップアップの候補に出る（レジストリとテンプレートが持つ `category` を足して返す）
  - 読み込み時に「全て入れ替える」「末尾に追加」「カテゴリにして追加」の 3 択を出す（フォーカスは「末尾に追加」、Esc と背面のクリックで読み込まない）
    - 「全て入れ替える」は 2 段階目の確認（いまの N 件とグループ M 件を消します。元に戻せません）を挟み、「戻る」で選択画面に戻る
    - 「カテゴリにして追加」は読み込んだテンプレートを全部「追加されたカテゴリ」にする。2 回読み込んでも同じ 1 つのカテゴリに集まる。読み込み後は一覧もそのカテゴリに切り替わる
    - 従来「一覧の先頭に寄せる」だった読み込みは「末尾に追加」に変わった（並びを読む側の都合で崩さないため）
  - typecheck と build は通る。既存ハーネス（14 件 + 27 件）も通る。カテゴリでの一覧の切り替わり・グループの隠れ方・ポップアップの開閉・行サブメニュー・3 択の見た目は実機でのみ確認
- **行の「移動」からカテゴリも選べるようにし、グループもメニューで移動できるようにした**
  - テンプレート行の「移動」にカテゴリ移動先を足し、カテゴリ変更を同じ導線からできるようにした。従来の「カテゴリ」メニューも残してある
  - グループ行にも「移動」を足し、カテゴリの付け替えを行えるようにした
- **移動メニューをカテゴリ階層にした**（[ADR-009](../docs/ai/decisions/ADR-009-template-palette-group-categories.md)）
  - テンプレートの「移動」はカテゴリをホバーすると配下のグループが見える階層に変えた。グループの「移動」はカテゴリだけを選ぶ
  - グループに `category` を持たせ、カテゴリの付け替えや書き出し/読み込みでも残るようにした
- **移動メニューを 1 枚にまとめ、行の「カテゴリ」メニューを削除した**（[ADR-009 の追記](../docs/ai/decisions/ADR-009-template-palette-group-categories.md)）
  - カテゴリ → グループの 2 段サブメニューは、2 段目が 1 段目のスクロール枠で切れて見えなかった。テンプレートの「移動」は 1 枚の中に、カテゴリの見出しと、その下に字下げしたグループ（「グループ名（N件）」）を並べる形にした
  - カテゴリの見出しを押すと、そのカテゴリにしてグループから出し、ルートの末尾へ置く。グループを押すと、そのグループのカテゴリにして末尾へ入れる。今いる場所とカテゴリが同じものは押せない
  - グループの「移動」は今までどおりカテゴリだけ
  - カテゴリと並びは `MOVE` に任意の `category` を足して 1 回で書き換える。`SET_CATEGORY` と `MOVE` を別々に送っていたため、返事の順番が入れ替わると並びが戻って見えることがあった
  - typecheck と build は通る。メニューの見た目と移動の結果は実機でのみ確認
