## cbComponentExplorer

- **UI を cbTextChecker に合わせて作り直し、検索対象をターゲットだけにした**（[ADR-019](../docs/ai/decisions/ADR-019-component-explorer-target-only.md)）
  - 見出しエリア（「Component Explorer」と build 番号）、「現在の検索対象」と「選択／ページ／固定」のラジオ、固定先のコンボボックスを削除した
  - ターゲットが無いときの「Nodeが選択されていません」「固定先が未選択です」を出さず、一覧を空にするだけにした
  - ターゲットのボタンは cbTextChecker の `targetPicker.ts` を移植した。押すとキャンバスの選択（無ければ近い親）をターゲットにし、選択が無ければ「最近選択したフレーム」（clientStorage の `cbComponentExplorer.recentTargets`、20 件）と「候補一覧から選ぶ…」を出す。選択済みのボタンにホバーすると緑の破線枠（10px、セッション ID 付きの名前）を出す
  - ターゲットにできる種類を SECTION / FRAME / INSTANCE / GROUP に広げた。キャンバスの選択を変えても再検索せず、ターゲットを決めたときとページを変えたときだけ検索し直す
  - 下端のハンドルで高さを変えられるようにした（`uiHeight`、320〜900px）
  - 見た目（フォント・余白・区切り線・セグメント風のラジオ・行・トグルの色 `#18a0fb`）を cbTextChecker に寄せた。並び替え（レイヤー順・名前順）、Instance 一覧、トグルでの選択、ホバーのハイライトは今のまま

  - レイヤー順ではいちばん上のバリアントの位置とグループに置き、名前順ではセット名でほかの Component と混ぜて並べる。中はそれぞれレイヤー順・バリアント名順
  - 開閉の状態は UI のメモリだけに持つ（閉じると戻る）
  - 走査結果に `componentSet` と `variantName` を足した。ライブラリのコンポーネントセットへのジャンプも断るようにした

- **レイヤー順をレイヤーツリーから組み立て直した**（[ADR-020](../docs/ai/decisions/ADR-020-component-explorer-layer-tree.md)）
  - 報告: 複数の Section を含む Section をターゲットにすると並びがおかしい、出てこないコンポーネントがある、コンポーネントの中のインスタンスが階層にならない
  - 原因: 定義とインスタンスの並び番号を別々に数えて混ぜていて、向きもレイヤーパネルと逆だった。定義の場所に出すのはインスタンス 0 件のときだけだった。先祖パス方式では入れ子を表せなかった
  - 走査をターゲットの自前の深さ優先（子は末尾から = パネル順）にし、`result` に `layerTree` を足した。`definition` / `groupPath` / `ancestorPath` と `resolveAncestorPath` は消した
  - UI は `src/ui/layerItems.ts` の `buildLayerItems` で項目の木を作る。メインコンポーネント（「定義」バッジ）とインスタンスの行も、中にインスタンスがあれば ▸ / ▾ で開ける。同じ親の直下で同じコンポーネントのインスタンスは 1 行にまとめる
  - トグルは行の経路キー（`item:<経路>`）、Instance 一覧は行のインスタンス id で絞る。場所ごとの `scopeId` の仕組みは消した
  - typecheck・build は通る。`buildLayerItems` は node で確認した（Section 内の複数 Section の順、定義の中のインスタンス、インスタンスの中のインスタンス、外で使われている定義）。Figma の実機は未確認
