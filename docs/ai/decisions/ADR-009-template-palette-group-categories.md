# ADR-009: グループにも category を持たせ、移動メニューをカテゴリ階層にする

- ステータス: 採用
- 日付: 2026-10-06
- 関連: [ADR-005](ADR-005-template-palette-groups.md)、[ADR-008](ADR-008-template-palette-categories.md)

## コンテキスト

`cbTemplatePalette` では `TemplateMeta.category` によってテンプレートのカテゴリを切り替えていたが、移動メニューはテンプレートの所属先だけを見せており、カテゴリとグループの関係が UI に出ていなかった。ユーザーは「移動」にホバーしたときに、カテゴリを先に見て、その配下にグループを辿れる形を求めていた。

グループ自体にもカテゴリの概念が必要になったが、これはグループの入れ子化ではない。グループはあくまで 1 階層の入れ物のまま、表示と選択のための属性として category を持たせる。

## 決定

- `TemplateGroup` にも任意の `category` を持たせる
  - `category` が無いときは「未設定」
  - グループの入れ子は作らない。カテゴリ配下に見えるのは root のグループだけ
- テンプレートの「移動」は、カテゴリをホバーするとその配下のグループを見せる階層メニューにする
  - カテゴリ単体での変更も、同じ「移動」導線に含める
  - テンプレートがグループへ移るときは、そのグループの category も同時に反映する
- グループの「移動」はカテゴリの付け替えだけにする
  - 並び順の変更は従来どおりドラッグで行う
- `listCategories()` はテンプレートとグループの両方からカテゴリ名を集める
- カテゴリ名の変更はテンプレートだけでなくグループの category もまとめて付け替える

## 結果

- `tree` にグループの category が残るようになり、読み込み・書き出しでも失われない
- 移動メニューは「カテゴリ → グループ」の順でたどれる
- `ADR-008` の「カテゴリはグループとは別」という方針は、テンプレートの保存先ラベルとしては維持しつつ、移動 UI のためにグループへも category を持たせる形で拡張した

## 追記: 移動メニューを 1 枚にまとめる

- 最初の実装は「カテゴリ → グループ」を 2 段のサブメニューにしていた。サブメニューは `overflow: auto` で左に開くため、2 段目は 1 段目の枠で切れ、360px 幅では左端からもはみ出して、グループが見えなかった
- テンプレートの「移動」は **1 枚のサブメニューに、カテゴリの見出しと、その下に字下げしたグループを並べる** 形にした（ユーザーの指定）
  - カテゴリの見出しも押せる。押すと **そのカテゴリにして、グループから出してルートの末尾へ置く**（ユーザーの指定）。カテゴリだけ変えて別カテゴリのグループに残すと、グループの category と食い違うため
  - グループを押すと、そのグループの category にしてグループの末尾へ入れる
- 行の「⋯」にあった「カテゴリ」メニューは削除した。「移動」の見出しで同じことができ、グループとの食い違いも起きないため
- グループの「移動」でカテゴリを変えると、**中のテンプレートのカテゴリも同じものに書き換える**。一覧はテンプレートの `category` で絞るので、グループだけ変えても今のカテゴリに残って見えていた。テンプレートをグループへ入れるときにグループのカテゴリへ揃えるのと同じ考え方
- **中身が 0 件のグループは、グループの `category` が今選んでいるカテゴリと同じときだけ出す。** 中身で絞れないため以前は全カテゴリに出ていて、グループの最後の 1 件を別カテゴリのルートへ出すと、空のグループが移動先にも現れていた
  - そのかわり、新しく作るグループには今選んでいる保存先カテゴリを付ける（`ADD_GROUP` に任意の `category`）。付けないと、未設定以外を見ているときに作った直後に消えるため
- カテゴリの書き換えと並びの変更は、`MOVE` に任意の `category` を足して 1 回で送る。`SET_CATEGORY` と `MOVE` を別々に送ると、プラグイン側の処理が並行して返事の順番が入れ替わり、古い一覧が後から届いて並びが戻って見えることがあった
