# ADR-003: テンプレートはノードを独自 JSON に変換して clientStorage に保存する

- ステータス: 採用
- 日付: 2026-10-02

## コンテキスト

`cbTemplatePalette` は、選択した frame / section / group を保存し、あとで複製できるようにするプラグイン。ユーザーは、保存した要素を**別のファイルでも**使えることを求めた。

Figma のプラグイン API には、ノードをそのままファイルの外へ持ち出して、別のファイルで復元する手段がない。同じファイル内であれば、専用ページに原本を複製して `clone()` すれば完全に再現できる。しかし、この方法はファイルをまたげない。

## 決定

- ノードツリーを、プロパティ単位で独自の JSON（`SerializedNode`）に変換する。復元時は、プラグイン API でノードを組み立て直す
- 保存先は `figma.clientStorage` にする。ユーザー単位・プラグイン単位で保存され、どのファイルからでも読める
  - 一覧用の情報（`index`）と本体（`item.<id>`）を分け、一覧の表示で本体を読まずに済むようにする
- 画像は、`getImageByHash().getBytesAsync()` のバイト列を `Uint8Array` のまま保存する。復元時に `figma.createImage` で作り直し、塗りのハッシュを付け替える（下の追記で廃止。画像は保存せず、複製時は単色にする）
- 座標は、テンプレート左上を原点とした絶対変換行列で持つ。復元時に配置先コンテナの座標系へ変換する。これで、グループやブーリアン演算（独自の座標系を持たない）や回転にも対応できる
- オートレイアウトは、子を入れたあとに `layoutMode` などを設定し、最後にサイズ指定モードを戻す（`resize` が FIXED に変えてしまうため）

## 結果

- 別のファイル・別のページでも、一覧から複製できる
- 形を変えて再現するもの
  - インスタンスとコンポーネントは通常のフレームになる（detach 相当）。元のコンポーネントとのつながりは失われる
  - スタイルと変数の紐付けは外れ、値だけが残る
  - 復元先の環境に無いフォントは、同じファミリーの Regular、なければ Inter Regular に置き換える。置き換えた件数は通知する
    - 対応外のノード（スライス、コネクタ、ウィジェット、埋め込みなど）と動画の塗りはスキップする（2026-10-05 の追記で ルートの扱いを変更）
- 容量はプラグインごとに約 5MB。画像を多く含むテンプレートはすぐに上限に近づく。使用量を UI に表示し、上限を超える保存は拒否する
- 保存データは端末の Figma に置かれるため、他のユーザーとは共有されない

## 追記（同日）: 容量の節約とファイルへの書き出し

### コンテキスト

5MB では足りないという声があった。`clientStorage` の上限は Figma が決めた固定値で、プラグイン側から引き上げられない。プラグインの画面は出どころを持たない iframe で動くため、`localStorage` や IndexedDB も使えず、フォルダへの直接アクセス（File System Access API）も許可されていない。

### 決定

- 画像のバイト列は保存しない。容量の大半を占めるため。画像ハッシュだけを残す
- 複製時は、画像の塗りを常に単色（`#D9D9D9`）に置き換えて件数を通知する（ユーザーの指定）。同じファイルに元の画像があっても使わず、version 1 で保存した画像データも使わない。どこで複製しても結果が同じになる
- ノードツリーの JSON は fflate の `gzipSync` で圧縮し、`Uint8Array` で保存する（`Uint8Array` は JSON に変換されず、そのままのバイト数で数えられる）。main のサンドボックスには `CompressionStream` が無いため、同期で動く fflate を選んだ
- サムネイルは PNG 240px から JPG 120px に変える（表示は 48px）
- 保存形式を version 2 とし、初版の version 1 は読み込みだけ対応する
- 5MB を超えて手元に残したい分は、パソコンへのファイルの書き出しと読み込み（`*.cbtemplate.json`）で扱う。ファイルにも画像は含めない
- 自前の Web ページをプラグイン画面にして IndexedDB を使う案と、`localhost` の保存用アプリの案は、公開や配布の負担が大きいため見送った

### 結果

- 画像を含むテンプレートを複製すると、画像の部分は常に単色の塗りになる
- ファイルの書き出し・読み込みは毎回保存先やファイルを選ぶ必要がある。その代わり容量の制限はなく、他の人にも渡せる

## 追記（2026-10-05）: ルート（集团の親）にも基本シェイプを保存できるようにする

### コンテキスト

保存ボタンが受け付けるのは frame / section / group / component / instance だけで、四角形やテキストを 1 つだけ選ぶと保存できなかった。一方、シリアライズと復元は子のレベルでは矩形・楕円・ポリゴン・星・直線・ベクター・ブール演算・テキストをすでに扱っており、保存できない原因は「ルートで受け付ける型」の許可リスト 1 つだけだった。

また、保存できない型を複数選択に混ざせたとき、以前は対象外のノードを黙って捨てて保存していた。

### 決定

- ルートの許可リストは「コンテナ + シリアライザが往復できるすべてのシェイプ / ベクター / ブール演算 / テキスト」とする。型を 1 つ増やすたびに 2 箇所を直さないよう、シリアライズ側と同じ集合定数を共有する
- 復元できない型（スライス、コネクタ、ウィジェット、埋め込み、スライド系など）がルートに混ざっている場合は、除外して部分的に保存させず、**保存せずエラーにする**。黙って一部だけ保存すると、ユーザーは何を失ったのか分からなくなる
  - 保存対象の件数を 0 と伝えて保存ボタンを出し、ヒントに混ざった件数だけを出す
  - `handleSave()` 側にも同じ判定を残し、ボタンの状態に頼って守りを置かないようにする
- 子にできない型があるノードをネストしたときの挙動は変えない。従来どおりスキップして件数を通知する（この追記で変えたのは「ルート」の話だけ）
- 複数選択のサムネイルは全ルートを対象にする。ルートが複数なら画面外で一時グループにまとめて書き出す。section はグループにできないため、その場合は従来どおり先頭のルートだけを使う

### 結果

- 図形やテキストだけのテンプレートが、フレームと同じ手续で保存できる
- 選択に混ざった保存できない要素は画面に理由として現れる
- 複数選択のサムネイルを書き出すため、画面外（ビューポートの右 1000px さき）に一時グループが 1 つできる（書き出し後はまとめて削除する）
