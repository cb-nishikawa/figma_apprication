# ADR-008: カテゴリはグループとは別のラベルとして持ち、保存先と一覧の表示を同時に切り替える

- ステータス: 採用
- 日付: 2026-10-06
- 関連: [ADR-005](ADR-005-template-palette-groups.md)（並び順とグループ）、[ADR-003](ADR-003-template-palette-serialization.md)（保存形式）

## コンテキスト

テンプレートは増える一方で、探す手段は名前の絞り込みとグループだけだった。グループは「入れ物」と「並び順」を同時に意味するため、「ヘッダー周りは全部並べておきたいが、色のテンプレートも同じグループに入れたい」といった分け方ができなかった。ファイルをまたいだ受け渡しでも、相手のグループ構成と自分の並びが食い違う。

## 決定

- **カテゴリは `TemplateMeta.category`（任意の文字列）で、1 件につき 0 か 1 個。** グループとは独立で、並び順も入れ替えもしない
  - 無しは「未設定」と表示する
  - `meta` は自由形なので **ファイル形式の version は上げない**。`templates[].meta` に入れて書き出すだけで、`category` を知らない読む側は無しとして読める
- **保存先のカテゴリはヘッダー右のボタンで選ぶ。** ポップアップの中は「未設定」と登録済みのカテゴリ名の並びで、**選ぶと一覧の絞り込みと保存先を同時に変える**
  - 一覧は選んだカテゴリの行だけを出す。「未設定」は `category` が無い行だけ。名前の絞り込みとは AND で併用する
  - 起動時の既定は「未設定」。この選択は **UI のセッション内だけ**で、次に開くと必ず「未設定」
  - 画像の確認ダイアログを挟んでも、同じカテゴリをもう一度送る
- **カテゴリで絞ったときのグループは、名前の絞り込みと同じ扱い**
  - 中身が 1 件も合わないグループは隠す。中身の一部だけが隠れるグループは、たためていても開いた状態で描く（折りたたみ状態は保存したまま）。全部が残るグループはたためたまま
  - 中身が 0 件のグループ（作ったばかりのもの）は名前を絞っていない限り出したままにする。入れられない場所だとグループを作れないため
- **カテゴリの登録先は `cbTemplatePalette.categories`（名前の配列）。** 使っていない名前も残る
  - 追加: 見出しの「⋯」→「カテゴリを追加」。名前は「カテゴリ N」で開き、そのままでも打ち直してもよい
  - 名前変更: ヘッダーのポップアップの「名前を変更」。レジストリと、そのカテゴリを持つ `meta.category` をまとめて書き換える
  - 削除 UI は作らない
- **保存済みの 1 件は行の「⋯」→「カテゴリ」→ 名前で書き換える**（現在のものは選べない）
- **ファイルの読み込みは 3 択**: 「全て入れ替える」「末尾に追加」「カテゴリにして追加」
  - カテゴリにして追加 = 末尾に追加と同じうえで、すべての `meta.category` を固定の **`追加されたカテゴリ`** にしてレジストリにも足す（2 回読み込んでも 1 つのカテゴリに集まる）
  - 全て入れ替えるは 2 段階目の確認（いまの N 件とグループ M 件を消す）を挟む
  - カテゴリのレジストリ自体はファイルに書かない
- 一覧の並びとグループの構造は `tree.ts` のままで、**カテゴリは並びを触らない**

## 理由

- グループをラベル兼並び順にすると、並べ替えたくて作ったグループが「ファイルを渡したときに勝手に変わる」ものになる。分けておくと、並びを渡すかどうかをラベルと無関係に決められる
- 「どこに入れたか」は、選んだ直後に**見えていないと意味がない**。保存先を選ぶだけで一覧が変わらないと、カテゴリを作っても保存した要素が切り替わらないままになる。保存ボタンの直前に置いて、選ぶことと表示が 1 つの操作で完結する
- 保存先を永続化すると次に開いたときに見落としやすいので、毎回未設定から始める
- 読み込んだファイルが持つカテゴリは、自分のレジストリに無いことがある。`listCategories` はレジストリとテンプレートが持つ `category` を足して返すことで、この不一致を吸収する
- カテゴリの削除は「使わなくなった名前だけが消える」という保証をつくる操作になる。使う範囲を追加・名前変更に絞る

## 却下した案

- **カテゴリをグループの属性にする** — グループ 1 つにつき 1 つしか持てなくなり、2 つ以上を付けられない。グループには「削除すると中のテンプレートも消す」という既存の意味があるため、ラベルを混ぜない
- **複数カテゴリ（`string[]`）** — 保存先は 1 つなので、持つ側と選ぶ側の数が食い違う。最初の需要は「どこに入れたか」だけ
- **表示は変えず、保存先だけを選ぶ（当初の設計）** — 保存した要素が切り替わらず、カテゴリを作っても一覧が変わらない。「どこに入れたか」が見えないので、選んでも意味が伝わらない
- **「すべて」を先頭に足し、既定を「すべて」にする** — 起動直後は全部「未設定」なので見た目は同じだが、選んでいるものが曖昧になる。「未設定」を既定にすると最初から表示と保存先の意味が通る
- **カテゴリを一覧の行に常時表示する** — 詳細 60px / 一覧 44px に収まらず、サムネイルモードは 2 カラムなので高さも足りない。見るのは行の「⋯」の中だけにする
- **読み込みの 3 択を出さず、既定で末尾に追加する** — 読み込みは取り消せず、「入れ替える」は既存を消す。3 択と入れ替えの 2 段階確認は毎回出す

## 結果

- `TemplateMeta` に `category?: string` が増えた。`tree` は ADR-005 のまま（カテゴリは並び順に触れない）
- 一覧の出し分けは `visibleNodes()` の `hits` が担う。名前クエリと AND で、選んでいるカテゴリと一致する行だけを出す
- 起動時は「未設定」なので、既存テンプレートがすべて見えているうちは操作感が変わらない
- ファイル形式の version は据え置き（version 4 のまま）
- `ImportMode` = `replace` / `append` / `category`。読み込みは毎回ダイアログで選び、フォーカスは「末尾に追加」
- 既存テンプレートはすべて「未設定」。`cbTemplatePalette.categories` が無い環境では一覧は空から始まる

## 追記（2026-10-07）: カテゴリの削除と、文字のボタン

- 「削除 UI は作らない」を改めた。一覧の「⋯」→「カテゴリを削除」で、**今選んでいるカテゴリを、中のテンプレートとグループごと** 消す（ユーザーの指定）
  - グループの削除（中身ごと消す。ADR-005 の追記）と同じ扱いにそろえ、戻せないので「⋯」の中で件数つきの確認を挟む
  - 対象は「今選んでいるカテゴリ」だけ。一覧に見えているものがそのまま消える範囲になり、何が消えるかを取り違えにくい。未設定は消せない
  - 消したらレジストリからも外し、保存先は「未設定」に戻す
- ヘッダーのカテゴリボタンを、タグのアイコンから **今のカテゴリ名を出す文字ボタン**（幅 96px 固定、はみ出しは省略線）にした。どのカテゴリを見ているかを、ホバーせずに分かるようにするため。幅を固定するのは、名前の長さでヘッダーのほかのボタンが動かないようにするため
