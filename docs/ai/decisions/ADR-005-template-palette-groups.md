# ADR-005: テンプレートの並び順とグループを index と別のキーに保存する

- ステータス: 採用
- 日付: 2026-10-05

## コンテキスト

`cbTemplatePalette` の一覧は `cbTemplatePalette.index`（`TemplateMeta[]`）をそのまま表示していた。索引には名前・大きさ・サムネイルはあるが、並び順やまとまりの情報が一切ない。ユーザーから、次の要望が出た。

- 保存したものをグループにまとめたい（中身はそのままでよい）
- 並び順を自分で決めたい。ドラッグで動かしたい
- グループもファイルへの書き出し・読み込みに含めたい

このプラグインは 1 プラグインにつき約 5MB の `figma.clientStorage` しかなく、ツリーの読み込みは非同期（`getAsync`）である。保存・削除・並べ替えのたびに全件を読み直すのは避けたい。

## 決定

### 並び順とグループは index と分ける

- 新しいキー `cbTemplatePalette.tree` に、一覧の並び順とグループを入れる。`index` は `TemplateMeta[]` のまま変更しない
  - `index` は「何が存在するか」だけ、`tree` は「どう並んでいるか」だけを持つ。役割が分かれると、片方の更新が片方を壊さない
  - `tree` は小さい（id とグループ名だけ）なので、並べ替えのたびに読み直しても問題ない
- 保存・削除でも `tree` を必ず追従させる。削除はグループの中からも取り除くが、グループそのものは残す
- `tree` は index に合わせて **照合（reconcile）してから返す**。読み込むたびに
  - index にない id（削除されたもの、他ウィンドウで消されたもの）は落とす
  - `tree` が知らない id（グループ機能より前に保存したもの、同時に保存されたもの）はルートの先頭に足す
  - 同じ id が複数箇所にあるときは最初だけ残す
  - これにより「`tree` が index より古い」状態が常に自己修復する。移行処理が要らない
- 並べ替えの処理は純関数（[`src/tree.ts`](../../cbTemplatePalette/src/tree.ts)）に切り出し、Figma API に依存させない

### モデルは 1 階層だけ

- `TemplateGroup`（`type: "group"`, `id`, `name`, `items`）と `TemplateListEntry`（`type: "item"`, `id`）の和集合を `ListNode[]` とする
- `ListNode[]` がルートの一覧で、グループの中に `ListNode[]` は入れない。**グループは入れ子にしない**
  - 入れ子にするとグループ自身を中に入れられる必要がある。UI・並べ替え・照合・書き出しのすべてが再帰になり、1 階層で表現できる範囲に収めたほうがよい
- ルートにはグループとテンプレートを同じ順序で混在させる
- 作った直後のグループは空なので、**絞り込み中でなければ必ず一覧に出す**。テンプレートを入れられる状態にならないとグループを作れない。なお絞り込み中は一致するものが 1 件もないグループを隠す

### 操作の範囲

- グループは名前変更・削除・並べ替え・開閉。折りたたみは下記の追記で追加した（当初の決定は「入れない」）
- 新しく保存したテンプレートは常にルート（一覧の先頭）。保存時の所属グループは選ばせない
- グループの削除は、中身だけを元の位置に戻す（この節は同日追記の「削除は中身も消す」に置き換えられた）
- 並べ替えは 2 経路用意する
  - ドラッグ＆ドロップ（Pointer Events。4px 以上動いた時点で開始。行の上端・下端なら前後、その中央やグループ本体なら中に入れる）
  - 行の「⋯」→「← 移動」サブメニュー（ホバーで開く）。ポインタを使わずに選べる
- グループを別のグループの中に入れる操作は出さない（グループを別のグループにドロップしても動かない）

### ファイル形式は version 3

- `TemplateFile` に `tree?: ListNode[]` を足し、`version: 3` にする。`templates[].meta.id` を参照する
- version 2 のファイルには `tree` が無いので、読み込んだテンプレートはすべてルートに置く。version 3 でも `tree` が所述の id を網羅していない場合は、足りない分を末尾に足す
- 1 件だけ書き出すときは `tree` を平坦にする。1 件のテンプレートのためにグループを再現する意味がない
- id は読み込み時に振り直す（テンプレート・グループとも）。同じファイルを 2 回読み込んでも衝突しない

## 結果

- 並び順とグループが `clientStorage` に残る。ただし 2 つのキーを跨ぐ更新なので、途中で失敗すれば一時的にずれる。読み込み時の照合が直す
- グループは 1 階層。深い階層は作れない（作りたくなったら ADR を追加して再考）
- ドラッグ＆ドロップはデスクトップのマウスのみ。タッチでは動かず、行の「⋯」→「← 移動」で代替する
- 並び替えの純関数は Figma API なしでテストできる（今回は 47 ケースを node で実行して確認）

## 追記（同日）: グループをたためる

### コンテキスト

- グループ機能の修正が一段落し、その後で「グループをアコーディオンでたためるように」と要望があった
- 当初は「折りたたみは不要」として操作の範囲から外していたが、1 階層でも中身の量が多いと一覧が見えなくなり、自动生成されたグループを行き来するのが面倒になった

### 決定

- 開閉状態は `TemplateGroup.collapsed?: boolean` として、並び順と同じ `cbTemplatePalette.tree` に保存する。新しいキーは増やさない。**無い = 開いている** として扱うので、折りたたみ対応の前に保存された tree はそのまま動く
  - 別キー案は却下。開閉だけの更新で 2 つのキーをまたぐことになり、並び順とずれる機会が増える
- 開閉は `TOGGLE_GROUP` メッセージでコミットする（`MOVE` などと同じ保存経路）
- **ファイルには開閉状態を書かない**。ファイルが持つのは「中身の構成と並び順」だけで、読み込んだグループは全部開いた状態で出る
- 絞り込み中は、たたんでいても強制的に開いて描く。一致したテンプレートが隠れると検索結果を誰も読めないため。保存値は変えない
- 見た目は見出し左端のシェブロン button。1 つの SVG を `rotate(-90deg)` で回すので、JS 側で絵を使い分けなくてよい
  - シェブロンは独立した button にして、押してもグループは選択されない。ドラッグの開始位置からも除外する（押した途端にグループを動かせない）
  - たたんだときは入れ子 `ul` 自体を作らない。隠すだけだと drop の座標計算を間違う
- たたんだグループの上にドロップすると、自動で開いて中に入れる。移動結果が隠れないようにするため
- 件数（例: 12件）はたたんだまま出す。何が隠れているかが分かる

### 結果

- `setGroupCollapsed` という 1 つの純関数を足すだけで、名前変更・並べ替え・削除・照合はすべて自動で `collapsed` を引き継ぐ。**引き継がないのは意図した 2 つだけ**（`exportTree` と `parsedFileTree`）
- 開閉まわりは node で 20 ケース実行して確認した（toggle 15 ケースと、既存の並べ替え・照合のふるまい 5 ケース）。rename / move / removeItems / reconcile / appendMissingItems / addGroup は引き継ぎ、`remapTree` だけが落とすことを確かめた
- headless Chrome で実測した
  - たたみ: `aria-expanded="false"`、入れ子 0 件、シェブロンは `matrix(0,-1,1,0,0,0)`（= -90度）。見出しの高さは開いたときと同じ 34px で、折畳んでもレイアウトが動かない
  - 絞り込み: 一致した 2 件が見えて `aria-expanded="true"`。絞り込みを消すと再び `false` に戻る
  - シェブロンからのドラッグ: `is-dragging` にならない。グループ名からのドラッグは従来どおり動く
  - ルート行をたたんだグループにドロップ: 中身が `B,C,A` になり、自動で開いて、`MOVE` → `TOGGLE_GROUP=false` の順に送られる
- プラグインを開き直しても折りたたみ状態が戻るかは `clientStorage` を使うため、実機でのみ確認できる

## 追記（同日）: 削除は中身も消す。グループだけ書き出す

### コンテキスト

- グループを消すと中身のテンプレートがルートへ戻る動作では、並びを保ったまま整理はできるが「グループを消した」のに中身が残るので、意図と結果がずれる取り違えが起きやすかった
- 「グループをそのまま 1 ファイルとして持ち出したい」需要があった。既存の一斉書き出しは全体をまとめるだけで、1 グループだけを取り出す口がなかった
- 一方「中身を残してグループだけ外したい」需要もあるが、それは「中身を消したい」とは別の操作なので、メニューを混同させない

### 決定

- **グループを削除するときは、中のテンプレートも保存データごと消す**。戻す手段が無いので、`⋯` メニューの中で必ず確認を出す
  - 確認は専用モーダルではなく、同じ行メニューのパネルを「「グループ名」と中の N 件を削除します（元に戻せません）」に差し替える形にする。プラグインの iframe では `window.confirm` が安定しないため
  - メニューを開き直したときは「削除」から入り、確認の画面は毎回リセットされる
  - 「キャンセル」は元のメニューに戻る
  - 「グループだけ解除（中身は残す）」は出さない。中身を残したいなら、行をグループの外へ移動してから消せば足りるとした
- 実装は `tree.ts` の `dropGroup`（グループだけ落とす）と `storage.ts` の `deleteTemplates(ids, dropGroups)`（index と item と tree を 1 回ずつ書く）。以前の `removeGroup`（中身をルートへ戻す）は不要になったので削除した
- **グループだけ書き出す**口を作る。メッセージは `EXPORT_GROUP { id }` で、既存の `EXPORT { ids }` とは別にする
  - `EXPORT` の `ids` 指定は `tree` を平坦化するので、グループを指定するとグループ情報が落ちる。前身が分かる形を残したいので別のメッセージにした
  - 出力は version 3 のまま。`tree` にそのグループ 1 つだけ入れるので、読み込んでも同じ名前・同じ中身のグループとして戻る（読み込み側は変更なしで動く）
  - ファイル名は `<グループ名>.cbtemplate.json`。中身が無いグループはエラーにする（空のファイルを黙って作らない）
- 名前の変更は、一覧の名前だけでなく**保存データの中の要素名とサムネイル**も揃える。キャンバス上の元要素には触れない
  - ルートが複数あるテンプレートは要素名を変えない。一律に同じ名にすると、中身が「カード A」「カード B」のまま 1 つに潰れた名前になって違いが読めなくなる
  - コンポーネントのテンプレートは複製時に元コンポーネントを clone するので、複製後のレイヤー名はキャンバス側の名のままになる。これも仕様として明記する

### 結果

- 削除は元に戻せないので、書き出してから消す運用を前提にし、確認表示でそれを伝える
- `deleteTemplates` にまとめたことで、1 件削除のときの書き込み回数は从前と同じ（index 1 / tree 1 / item 1）。空グループを消すときは item の削除が 0 件になる
- 一覧の名前は「ファイルに書かれた名前」→「保存データの要素名」→「テンプレート」の順で決まり、「読み込んだ〜」のような冗長な言い回しは出ない
- node のふり（`clientStorage` と `postMessage` だけの最小モック）で 45 ケース確認した。グループ削除（index / item / tree / 通知）、名前変更（要素名・サムネ・容量・複数ルート・空名）、グループ書き出し（tree・グループ名・件数・空グループ）、書き戻したときの名前とグループが戻ることを見た
- サムネイルの描き直しはキャンバスが要るので、失敗しても前のサムネイルを残す（消さない）。実機でのみ確認できる
