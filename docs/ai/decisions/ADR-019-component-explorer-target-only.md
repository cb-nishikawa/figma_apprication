# ADR-019: Component Explorer の検索対象をターゲットだけにする

- ステータス: 採用
- 日付: 2026-10-24
- 関連: [ADR-002](ADR-002-session-scoped-overlays.md)

## コンテキスト

ユーザーは「cbComponentExplorer を cbTextChecker の UI に合わせて作り直して」「対象を選ぶときはターゲットのみでいい」と求めた。あわせて、見出しエリア（Component Explorer・build 番号）、「現在の検索対象」の選択、「Nodeが選択されていません」の文言を消すよう求めた。

これまでは「選択／ページ／固定」の 3 つの検索対象をラジオで切り替えていた。選択モードはキャンバスの選択が変わるたびに再検索していた。固定モードはコンボボックスで Section / Frame を選んでいた。cbTextChecker は、ターゲットのボタン 1 つ（選択から決める・履歴・候補一覧・ホバー枠）で検索対象を決めている。

## 決定

- 検索対象はターゲットだけにする。選択モード・ページモード・ラジオ・固定先のコンボボックスは削除する
- ターゲットの選び方は cbTextChecker と同じにする（`src/targetPicker.ts` を移植）
  - ボタンを押すと、キャンバスの選択（無ければ近い親）をターゲットにする
  - 選択が無ければ「最近選択したフレーム」（clientStorage の `cbComponentExplorer.recentTargets`、20 件、起動時に消えたノードを掃除）を出す
  - ホバーで緑の破線枠を出す。枠の名前に起動ごとのセッション ID を付け、ほかの人の枠を消さない（ADR-002 と同じ考え方）
- ターゲットにできる種類を、cbTextChecker と同じ SECTION / FRAME / INSTANCE / GROUP に広げる（これまでは SECTION / FRAME）
- キャンバスの選択が変わっても再検索しない。選択との同期表示（一覧の選択ハイライト）だけ続ける。再検索はターゲットを決めたときとページを変えたとき
- ターゲットが無いときは文言を出さず一覧を空にする
- 下端のドラッグで高さを変え、clientStorage の `uiHeight` に保存する（320〜900px、幅 360px）
- ビルドは esbuild のまま（cbTextChecker の Vite には移さない）

## 結果

- ページ全体の検索はできなくなる。ページ全体を見たいときは、ページ直下の Section や Frame をターゲットにする
- 選択するたびに再検索しなくなるので、一覧のトグルやジャンプで選択を変えても一覧が組み直されない
- 2 つのプラグインで、検索対象の選び方と見た目がそろう
