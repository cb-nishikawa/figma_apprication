# ADR-007: テンプレートの画像は保存のたびに確認し、含める場合はバイト列を保存する

- ステータス: 採用
- 日付: 2026-10-06
- 関連: [ADR-003](ADR-003-template-palette-serialization.md)

## コンテキスト

[ADR-003](ADR-003-template-palette-serialization.md) の追記で、テンプレートの画像はバイト列を保存せず、復元時に単色へ置き換えることにした。理由は `figma.clientStorage` の容量が約 5MB で固定であり、画像を入れたときに保存が成立しなくなるという不安があったため。

実際に使うと、単色化は「画像を保存しなかった」という事実を隠すので、ファイルをまたいだ複製で「画像が消えた」と誤解される。ユーザーからも、画像を消さないでほしい／入れるかどうかを聞かれたときに選び”的要求があった。

## 決定

- **保存のたびに、選択に画像があるときだけ確認する。** ダイアログは「画像を含める」／「画像を含めない」／「キャンセル」。Esc とカードの外は `キャンセル` と同じで、保存自体をやめる
- **`含める` を選んだときだけ** `figma.getImageByHash().getBytesAsync()` でバイト列を取って保存する。`StoredTemplateV3.images` は JSON（gzip）と同じ item の中に置く
- **`含めない` を選んだときはバイト列を取らない。** 代わりにノードを枠線プレースホルダへ置き換える
  - 中身が無いノードは `FRAME(name="image") > TEXT(name="image")` に置き換える
  - 中身があるノード（子を持つ、または TEXT）は、枠線の中に元のノードを置いて画像塗りだけ外す。型・子・テキスト・角丸・自動レイアウトは保つ
  - 形の一部（線・ベクター領域・文字の途中）は単色 `#D9D9D9` にする。消すと形が崩れるため
- **コンポーネント複製では `meta.imageMode` でこの選択を再現する。** `keep` なら `clone()` したものをそのまま、`placeholder` なら複製後に枠線へ置き換える
- **容量は「含める」を選ぶ前に判定する。** `ASK_IMAGES` に残量と合計を渡し、画像バイト列 + サムネイル余力（64KB）が残量を超えるなら「含める」を無効にする

## 理由

- 5MB の上限は変わらないが、画像を消して保存することを既定にしないので、容量と品質をユーザーが選べる。5MB に入り切らないときは明示的に警告される
- 確認を省略しないのは、保存という操作に「何が残るか」を含めるため。「含めない」を既定にすると「保存したのに画像が失われた」ことになる
- 復元失敗（4096px 超・非対応形式・読めないバイト列）は単色の枠線へ落とす。これで Figma の制約でも静かに壊れない

## 却下した案

- **「画像を保存する」チェックボックスを一覧に常時出す** — 一覧が毎回ずれる。画像があるときだけダイアログを出す方が自然で、場所も変わらないので迷わない
- **バイト列を JSON の中に `data:` URL で埋め込む** — ノードツリーごと gzip が効きにくくなる。JSON と同じ item の別キー（`images`）に分ける方がツリーの圧縮率を保ちやすい
- **容量を超えるときは保存自体を拒否する** — 画像を落とせば保存できるのに、画像なしの保存まで一緒にできなくなる。容量が足りない場合だけ「含める」を無効にする
- **非対応形式は `createImage` に渡して例外を吐かせる** — 保存したはずのテンプレートが開けない。取得時点で諦めて枠線にする

## 結果

- 保存形式が `StoredTemplateV3`（`data` + 任意の `images`）になる。version 2 のテンプレートはそのまま読み込める（画像は枠線に戻る）
- version 1 のテンプレートに残っていた `images` は復元に使い始める
- ファイル書き出しは画像がある場合だけ `version: 4` とし、`templates[].images` に `data:…;base64,…` を入れる。画像が無ければ version 3 のまま
- [ADR-003](ADR-003-template-palette-serialization.md) の「画像は保存せず単色にする」追記は本 ADR で置き換えられた（superseded）
