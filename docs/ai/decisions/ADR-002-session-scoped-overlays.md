# ADR-002: オーバーレイのレイヤーを起動ごとのセッション ID で分ける

- ステータス: 採用
- 日付: 2026-10-02

## コンテキスト

`cbTextChecker` のハイライト（ホバー・プール・OCR ラベル）と、`cbImageExport` のホバー枠（`hoverEffect`）は、ページ直下にレイヤーを作って表示している。`cbTextChecker` は掃除のたびに、固定名（`__CB_TC_HIGHLIGHT__` など）に一致する、または固定名で始まるページ直下のレイヤーを**すべて**削除していた。

同じファイルを複数人で開いて同時にプラグインを使うと、全員が同じ名前のレイヤーを作る。そのため、あるユーザーの掃除で別ユーザーのハイライトまで消えるという衝突が起きた。

## 決定

- プラグインの起動ごとに、ランダムなセッション ID（`Math.random().toString(36).slice(2, 10)`）を main スレッド側で 1 つ発行する
- オーバーレイのレイヤー名にセッション ID を含める
  - `cbTextChecker`: `__CB_TC_HIGHLIGHT__@<id>`、`__CB_TC_HIGHLIGHT_POOL__@<id>`、`__CB_TC_OCR_LABEL__@<id>:<key>` など
  - `cbImageExport`: `hoverEffect@<id>`
- 名前で削除するときは、**自分のセッション ID を持つレイヤーだけ**を対象にする。他人のセッションのレイヤーには触れない
- セッション ID 導入前のバージョンが残した、ID なしの旧名レイヤーは掃除の対象に含める（取り残しを防ぐため）
- `cbTextChecker` の対象候補一覧（検索・比較・画像ターゲット）からは、`__CB_TC_` で始まるオーバーレイを除外する。他ユーザーのプールグループが候補に出ないようにするため

## 結果

- 複数人が同時に使っても、互いのハイライト・ホバー枠を消さない
- プラグインが異常終了するなどして閉じる処理が走らなかった場合、そのセッションのレイヤーは自動では消えない。次の起動では別の ID になるため、手動で削除する必要がある（レイヤーはロック済み、もしくは名前で判別可能）
- 旧バージョンを使っているユーザーと同時に使った場合、旧名レイヤーは新バージョン側の掃除で消える可能性がある
