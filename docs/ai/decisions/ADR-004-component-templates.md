# ADR-004: コンポーネントのテンプレートは、同じファイルなら clone、別のファイルなら組み立て直す

- ステータス: 採用
- 日付: 2026-10-02

## コンテキスト

`cbTemplatePalette` にコンポーネントを登録したい、という要望があった。複製したときに、中のインスタンスやスロットなどをそのまま残し、すでにあるコンポーネントとは別の新しいコンポーネントとして置きたい。

これまでのテンプレート（[ADR-003](ADR-003-template-palette-serialization.md)）は、インスタンスもコンポーネントもフレームとして復元する（detach 相当）。そのため、この要望には応えられない。

Figma の `ComponentNode.clone()` と `ComponentSetNode.clone()` は、元とはつながらない新しいコンポーネント（セット）を作る。中身はすべてそのまま残る。ただし、元のノードがあるファイルの中でしか使えない。

## 決定

- COMPONENT か COMPONENT_SET を 1 つだけ選んで保存したものを、「コンポーネントのテンプレート」（`kind: "component"`）とする
- 同じファイルか別のファイルかで、複製の仕方を変える（ユーザーの指定）
  - **同じファイル**: 元を `clone()` する。完全に再現でき、実装も単純なため
    - 中身は保存した時点ではなく、今の元のコンポーネントのものになる
  - **別のファイル、または元が削除されていた**: 保存データから組み立て直す
- 同じファイルかどうかは、保存時に元のノードへ付ける `pluginData("cbTemplatePalette.stamp")` と、ノード id の両方で判定する
  - ノード id はファイルごとに振られ、別のファイルで同じ id の別ノードがありうるため
  - プラグインからは、公開プラグインでファイルを識別する手段（`figma.fileKey`）が使えない
- 組み立て直しでは、コンポーネント、セット、スロット、プロパティ定義と参照、インスタンスを、本物として作り直す
  - インスタンスの元コンポーネントは、次の順に探す
    1. ライブラリ（key で読み込む）
    2. このファイル（id で取り、key で照合）
    3. 前回作り直したもの（`sourceKey`）
    4. 埋め込んだ定義から新しく作る（ユーザーの指定）
    5. それでも無ければ、フレームにする
  - ライブラリに公開されていない元コンポーネントは、保存時に定義ごと埋め込む。公開されているものは key だけを残す（容量を抑えるため）
  - 新しく作った元コンポーネントは、複製したものの右にセクション「テンプレパレット: 部品」を作ってまとめる。`sourceKey` を付け、同じページで次に複製するときは使い回す
- 画像は、これまでの決まりどおり、どちらの経路でも単色にする。`clone()` の場合は、複製したあとで塗り替える（中のインスタンスはオーバーライドとして塗り替え、元のコンポーネントは変えない）
- 複数を選んだ場合と、INSTANCE を選んだ場合は、今までどおりレイアウトのテンプレートとして扱う

## 結果

- 同じファイルでは、中のインスタンス、スロット、プロパティ、オーバーライドがすべて残った新しいコンポーネントになる
- 別のファイルでは、次のものは再現しきれない場合がある
  - インスタンス内のオーバーライド: 子を並び順で対応させ、塗り・線・エフェクト・不透明度・表示・名前・角丸・テキスト・サイズを当て直す。それ以外の項目は当て直さない
  - インスタンス内のスロットの中身: 中身を作り直すため、元の初期値へのつながりは切れる
  - 変数とスタイルの紐付け、ライブラリが有効でない場合のライブラリのコンポーネント（フレームになる）
  - 再現できなかった件数は通知する
- サムネイルは、コンポーネント系もフレームとして作る `flatten` で書き出す。部品を作らずに済み、見た目は同じになる
