# ADR-016: D1 の読み書きを減らす

- ステータス: 採用（Worker の書き込み方式は再デプロイ後に有効）
- 日付: 2026-10-14
- 関連: [ADR-013](ADR-013-template-palette-d1.md)、[ADR-014](ADR-014-template-palette-shared-settings.md)

## コンテキスト

ユーザーは「D1への読み込みと書き込みが多くないかチェックして」と求めた。

調べた結果:

- 定期的に読み直す処理（ポーリング）は無い。D1 に触れるのは操作したときと一覧を開いたときだけ
- Worker の SELECT と DELETE は主キー `(space, path, chunk)` の索引を使い、読む行は chunk の数だけ
- Worker への呼び出しの目安
  - 共有カテゴリを開く: ping・metadata・index・tree
  - 保存 1 回: 約 5 回
  - グループの開閉 1 回: index と tree の読み込み、tree の書き込み
- D1 の書き込みは保存 1 回で約 10〜15 行。無料枠（1 日 10 万行）には十分収まる

そのうえで、減らせる所が 4 つあった。ユーザーは 4 つとも直すことを選び、使い回しの時間は 10 秒にした。

## 決定

### 共有カテゴリのグループの開閉は端末に置く

- 開閉のたびに共有の `tree.json` を書き直していた。書き込みが増えるうえ、ほかの人の開閉まで変わっていた
- 共有カテゴリでは、開閉を clientStorage の `cbTemplatePalette.linkedCollapsed`（`Record<共有カテゴリの id, たたんでいるグループの id[]>`）に置く。`TOGGLE_GROUP` は D1 を読みも書きもせず、一覧も送り返さない（UI は押した時点で反映している）
- 一覧を送るときに、グループの `collapsed` を端末の値で上書きする。D1 の `tree.json` に以前の開閉が残っていても使わず、消しもしない
- ローカルのカテゴリは今までどおり `cbTemplatePalette.tree` に入れる

### Worker の書き込みを UPSERT にする

- 「その path の行を全部消して入れ直す」をやめ、同じ chunk は `INSERT … ON CONFLICT DO UPDATE` で上書きし、余った chunk だけ `DELETE … AND chunk >= n` で消す（1 回の `batch`）
- ローカルの D1 で `rows_written` を比べると、1 chunk の上書きが 3 行から 1 行に、3 chunk が 9 行から 3 行になった
- API は変わらない。効かせるには Worker の再デプロイが要る（しなくてもプラグインはそのまま使える）

### 保存先の確認を使い回す

- ping と `metadata.json` の確認、読み込み結果の使い回しを、`D1StorageAdapter` のインスタンスから、保存先（URL・スペース名・トークン）ごとのモジュールの `Map` に移した
- 設定の切り替えや共有カテゴリの登録の変更で保存先を作り直しても、同じ保存先なら確認をやり直さない。失敗したら次の操作でやり直す

### 読み込み結果の使い回しを 10 秒にする

- `index`・`tree`・`categories` の読み込み結果を 5 秒から 10 秒使い回す。カテゴリを行き来したときの読み直しが減る
- 自分が書いた値は書いた時点で覚えるので遅れない。ほかの人の変更は最大 10 秒遅れて見える

## 結果

- 共有カテゴリでグループを開閉しても D1 に触れない
- 再デプロイした Worker では、書き込み行数が約 3 分の 1 になる
- 共有カテゴリの開閉は人ごと・端末ごとになる（以前は共有されていた）
