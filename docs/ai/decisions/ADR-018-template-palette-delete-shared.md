# ADR-018: 共有カテゴリを D1 のデータごと削除する

- ステータス: 採用（Worker の再デプロイが必要）
- 日付: 2026-10-14
- 関連: [ADR-013](ADR-013-template-palette-d1.md)、[ADR-014](ADR-014-template-palette-shared-settings.md)、[ADR-017](ADR-017-template-palette-d1-batch.md)

## コンテキスト

ユーザーは「共有カテゴリを外すの下に、共有カテゴリの削除を追加」「削除されたらデータベースからも削除できるように」と求めた。

これまでの「カテゴリを外す」は、自分の端末の登録を消すだけで、D1 のデータは残していた（ほかの人も使っているため）。データを消す手段が無く、使わなくなったスペースが D1 に残り続けていた。

消し方は 2 通りあった。

- プラグインが一覧（`index.json`）にあるテンプレートと `index`・`tree`・`categories`・`metadata` を消す。Worker はそのまま使えるが、同時に保存して一覧から漏れたファイル（`items/` に残るもの）は消えない
- Worker に「スペースを丸ごと消す」を足す。漏れたファイルも消えるが、Worker の再デプロイが要る

ユーザーは Worker に足す方を選んだ。

## 決定

- 一覧の「⋯」で「カテゴリを外す」の下に「共有カテゴリを削除」を置く。共有カテゴリを見ているときだけ出す。「カテゴリを外す」（データは残す）は今のまま
- 確認は既存の確認欄を使う。「同じスペースを使っているほかの人の一覧からも消えます。元に戻せません。残すなら先に「すべて書き出す」で保存」と書く
- Worker の一括 API に `clear: true` を足す。`DELETE FROM objects WHERE space = ?` を、ほかの delete / put より先に同じトランザクションで行う。トークンの照合は今までと同じ
- 応答に `cleared: true` を付ける。今の Worker（ADR-017 の版）は知らないキーを無視して `ok` だけ返すので、プラグインは `cleared` が無ければ「Worker が古い版です」と出し、消えたことにしない
- 消せたら登録を外し、見ていれば「未設定」に戻す。その保存先の確認結果と読み込み結果（使い回し）も捨てる。消せなければ登録は残し、接続テストと同じ案内を出す（Worker の応答そのものは出さない）

## 結果

- 使わなくなったスペースを、プラグインから D1 ごと消せる
- 同じスペースを登録しているほかの人の登録は残る。次に開くと空のスペースになり、`metadata.json` が作り直される（データが戻るわけではない）
- `clear` を使うには Worker の再デプロイが要る。本番は再デプロイ済み（バージョン b83247d1）
