# ADR-001: 画像書き出し単位の解決（単一画像コンテナは枠、それ以外は画像ノード）

- ステータス: 採用（2026-09-24 改訂）
- 日付: 2026-09-24

## コンテキスト

当初はマスクや `clipsContent` 付き FRAME の「見た目」に合わせ、マスク範囲・フレーム範囲を1件として解決した。しかし、`clipsContent` なフレーム内に複数画像があると全画像が1件にまとまり、個別に書き出せないという問題が起きた。ユーザーは複数画像・マスクされた画像・画像を含むフレームを、それぞれ**別の行**として一覧したい。

一方で、枠（`clipsContent`）やマスクが**中身を切り抜いて表示している**場合、画像ノード自身の書き出し結果は「見た目」と一致しない（はみ出た部分まで含まれる）。ユーザーは「画面上で見えている切り抜き結果」が一覧・書き出しに現れることを求めた。

## 決定

`cbImageExport` の一覧行は、IMAGE fill を持つ可視ノードそれぞれについて `resolveRow` で解決する。

- マスクコンテナ（`isMask` 子を持つ GROUP / FRAME / COMPONENT / INSTANCE）内の画像が**ちょうど1枚**の場合 → 行はそのコンテナ
- それ以外で、最近傍の `clipsContent` 付き FRAME / COMPONENT / INSTANCE が画像の祖先にある場合 → **画像数にかかわらず**行はそのフレーム（スロット枠も含む）
- それ以外（クリップ・マスクなし） → 行は画像ノード自身

- マスクノード（`isMask`）自身はスキップ
- 行の `nodeId` で重複排除する。`visible === false` の枝は走査しない
- サムネイル・書き出し・リネーム・フォーカスは、すべてこの解決された行を対象にする

## 結果

- 同 1 枚の画像を「切り抜いて」表示する枠（マスク / `clipsContent`）は、その枠の見た目が1行になる
- `clipsContent` の親・スロットは、中身の画像数にかかわらずその枠を1行として書き出し対象にする
- 画像が枠に収まっている（クリップの実効がない）場合も1行になる
