# ADR-020: Component Explorer のレイヤー順をレイヤーツリーから組み立てる

- ステータス: 採用
- 日付: 2026-10-24
- 関連: [ADR-019](ADR-019-component-explorer-target-only.md)

## コンテキスト

レイヤー順の一覧は、インスタンスごとの先祖パス（Section / Frame）から見出しの木を組み立てていた。ユーザーから次の報告があった。

- 複数の Section を含む Section をターゲットにすると、並びがレイヤーと違う
- 出てこないコンポーネントがある
- メインコンポーネントの中のインスタンスが、コンポーネントの下の階層にならない

原因は次のとおり。

- 定義とインスタンスの並び番号を別々に数えて混ぜていた。番号の向きもレイヤーパネルの表示（上が `children` の末尾）と逆だった
- 見出しの順が「最初に入った行」で決まっていた
- 定義の場所に行を出すのは、インスタンスが 0 件のときだけだった
- 先祖パスの方式では、コンポーネントやインスタンスの中の入れ子を表せなかった

## 決定

- 走査は `findAllWithCriteria` をやめ、ターゲットを深さ優先で自前でたどる。子は末尾から回し、**レイヤーパネルの上から下の順**にする
- 走査結果に `layerTree`（`LayerNode` の木）を足す。残すノードは SECTION / FRAME / COMPONENT_SET / COMPONENT / INSTANCE だけで、それ以外（GROUP など）は子を親に繰り上げる
  - インスタンス・メインコンポーネントの中の FRAME は残さない（見出しにしない）
  - ターゲット自身は木に含めない。INSTANCE / COMPONENT / COMPONENT_SET をターゲットにしたときだけ、そのノード自身を根にする
- UI は `layerTree` を `buildLayerItems`（Figma に依存しない関数、`src/ui/layerItems.ts`）で表示用の項目の木に変える
  - SECTION / FRAME は見出し（中身が空なら出さない）
  - メインコンポーネント（定義）は「定義」バッジ付きの行。子は中のインスタンス
  - インスタンスはまとめずに 1 行ずつ出す。名前はレイヤー名、ホバー・トグル・ジャンプはそのインスタンス自身に効く。「メインへ」リンクでメインコンポーネントへ移動する
  - バリアントのインスタンスはセットにまとめない
  - 子を持つ行はアコーディオン（最初は閉じる）
- トグルは行ごとの経路キー `item:<経路>` で持ち、その行が表すノード id（インスタンス、または定義）を選ぶ。Instance 一覧は行ごとに扱う
- 名前順は今のまま（コンポーネントごとに 1 行、件数は全体）

## 結果

- 並びが、見出しとコンポーネントを交えてレイヤーパネルと一致する
- ターゲット内の定義は、外で使われていても定義の場所に必ず出る
- 同じコンポーネントが複数の場所に出る。行の件数・トグル・Instance 一覧はその場所の分だけ扱う
- 自前でたどるぶん、大きなターゲットでは `findAllWithCriteria` より遅くなりうる。300 ノードごとに処理を譲り、古くなった検索はそこで止める
