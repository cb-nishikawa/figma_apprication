# ADR-015: 保存する画像を圧縮し、共有カテゴリの容量を 20MB までにする

- ステータス: 採用（Figma の実機での確認が必要）
- 日付: 2026-10-14
- 関連: [ADR-013](ADR-013-template-palette-d1.md)、[ADR-014](ADR-014-template-palette-shared-settings.md)

## コンテキスト

ユーザーは次を求めた。

- 「画像を追加するときに、追加する前に画像を圧縮して容量を減らしたい」
- 「共有カテゴリを使用する場合、追加できる最大容量を20MBに抑えれるように設定して」

選んでもらったこと:

- 20MB は共有カテゴリ 1 つの合計（ローカルの約 5MB と同じ扱いで、使用量バーも出す）
- 圧縮は「長辺 1920px まで。1920px 以下ならそのサイズのまま。JPEG 品質 80%。透明があれば PNG」

## 決定

### 画像の圧縮

- 「画像を含める」で保存する画像を、確認ダイアログを出す前に常に圧縮する。ダイアログの容量と「残り容量が足りるか」も圧縮後の大きさで判定する
- 長辺が 1920px を超えるときだけ 1920px に縮める。透明が無ければ JPEG（品質 80%）、透明がある PNG は PNG で作り直す
- 作り直した方が元以上の大きさなら元のまま使う。GIF（アニメーションの可能性がある）と、読めない画像も元のまま
- 圧縮は UI の iframe の canvas で行う。main スレッドには画像を読み込んで描き直す手段が無く、`exportAsync` の JPG は品質を指定できず、透明の有無も分からないため
  - main が `COMPRESS_IMAGES { requestId, images }` を送り、UI が 1 枚ずつ作り直して `IMAGES_COMPRESSED` で返す
  - 返事はキューを通さずに受ける（待っているのがキューの中の保存処理なので、積むと止まる）
  - 30 秒返事が無ければ元の画像を使う。main 側でも元より小さいものだけを採る
- 保存のキーは元の画像ハッシュのまま。復元時に `figma.createImage(bytes)` で新しいハッシュに付け替えている（`deserialize.ts`）ので、中身が変わっても正しく貼れる
- 画像のキャッシュ（ハッシュごと、8MB まで）は圧縮後のバイト列を持つ。確認ダイアログと保存で 2 回圧縮しない

### 共有カテゴリの 20MB 上限

- `D1StorageAdapter.quotaBytes = SHARED_QUOTA_BYTES`（20MB）。保存・移動・読み込みの上限の判定は、もともと `storage().quotaBytes` を見ているので、スペースごとに効く
- `QuotaExceededError` は上限を受け取り、「保存容量の上限（約 20MB）を超えるため…」と出し分ける
- フッターは D1 のとき「Cloudflare D1 使用量 3.2MB / 20.0MB」とバーを出す。80% 以上で赤くなるのはローカルと同じ

## 結果

- 大きな写真を含めても、保存される量は長辺 1920px の JPEG ほどになる。小さな画像は大きさを変えない
- 共有カテゴリの使用量が見えるようになり、20MB を超える保存は断られる

## 未確認・既知の制約

- Figma の実機の UI（iframe）で `createImageBitmap`・canvas の `toBlob` が期待どおり動くかは未確認
- 20MB の上限はプラグインの中だけで守る。Worker には入れていないので、古い版のプラグインからは超えて書ける。複数人がほぼ同時に保存すると、わずかに超えることがある
- 今 20MB を超えているスペースは、読めるが、減らすまで保存できない
- 圧縮するのは今回から保存する画像だけ。保存済みのテンプレートや、ファイルから読み込む画像は作り直さない
- JPEG の EXIF（向き以外のメタデータ）は作り直すと消える
